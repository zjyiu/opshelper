# opshelper 管理员手册

管理员负责账号、共享模型连接、共享 Agent 目录与用户分配，以及每用户固定容器的运维。普通用户在聊天中只会看到已分配且已成功装配的智能体，但也可以在工作台“智能体目录”创建、编辑或删除自己的私有智能体（保存后自动分配给自己）。管理员不能检查、编辑或分配普通用户创建的私有智能体；已有的私有分配会保留且不可由管理员调整。普通用户看不到未分配给自己的共享智能体或其他用户的私有智能体。平台没有项目、项目成员、共享文件或共享定时任务。

## 推荐开通顺序

1. 在“智能体与分配 → 模型连接”配置 OpenAI 兼容接口、API Key、模型 ID 和默认模型。
2. 在“智能体目录”创建或检查 Agent，确认状态为“检查通过”并处于启用状态。
3. 在“用户管理”创建账号。
4. 在“用户分配”给该用户勾选智能体并保存。
5. 等待配置状态为“已就绪”，同时核对已应用/目标代次及实际/期望清单一致。
6. 让用户从对话页完成首次任务。

管理入口位于 `/gateway/admin`，默认进入用户管理。

## 用户管理

“用户管理”支持按账号或显示名搜索，并按角色筛选。创建用户时设置登录账号、显示名称、角色、初始密码和“保持容器运行”；密码至少 6 位。

编辑用户可修改账号、显示名称、角色、密码、启用状态和保持运行设置。停用用户会阻止使用，暂停其活动定时任务，取消尚未开始的定时执行，并进入运行环境撤销流程。重新启用后仍需确认 Agent 分配和装配状态。

不能停用、降级或删除当前登录管理员；系统始终要求至少保留一个启用的管理员。

“删除账号”会删除用户数据库记录、关联容器以及该用户整个数据目录，包含 workspace、OpenCode state 和受管快照。该操作不可恢复，执行前应按部署与备份流程保留所需数据。

## 模型连接

“智能体与分配 → 模型连接”维护全平台唯一的 `custom` 模型组：一个 OpenAI 兼容 `baseURL`、可选 API Key、多条模型 ID/显示名以及一个默认模型。模型 ID 只能使用字母、数字和 `._:/-`（可包含或以 `/` 开头），不能重复；配置非空模型时，接口地址必须以 `http://` 或 `https://` 开头。

保存会提高所有已有用户环境的目标代次。正在执行的用户先等待当前顶层任务结束，空闲用户进入装配；期间不能开始新任务。清空模型组会让聊天页不再显示模型选择器，并可能使未显式指定可用模型的任务无法执行。

## 智能体目录

每个 Agent 的事实源位于 `data/agents/<key>/`，界面可维护：

- 必需的 `agent.md`；
- `skills/<名称>/SKILL.md` 及其附属资源；
- `scripts/<文件名>`；
- 可选的 `mcp.json`。

编辑页左侧是按目录分组的文件树：`agent.md` 与 `mcp.json` 归在“定义与配置”，每个 Skill 是独立分组并标出是否已被 `agent.md` 引用，脚本单独一组；右侧只编辑当前选中的文件。未引用的 Skill 不会进入运行时。
创建智能体时，界面顶部只填写 `目录 key`；智能体名称与职责说明统一在下方 `agent.md` 的 frontmatter 中维护。

智能体编辑页既可以从“技能仓库”按 name 模糊搜索并多选导入，也可以像原来一样直接上传单个 ZIP Skill 包。直接上传的技能只保存到当前智能体，不会进入仓库。导入后系统会把技能加入 `agent.md` 的 `skills` 列表。运行时会加上 Agent key 前缀，并通过 `permission.skill` 只授权给所属 Agent，避免同一用户其他 Agent 意外调用。

## 技能仓库

管理控制台新增“技能仓库”页面（侧栏位于“容器管理”下方），用于统一维护可导入技能：

- 支持按技能 `name` 模糊搜索；
- 管理页和导入界面均默认只显示两行 description，点击技能说明可展开全文；
- 支持全选当前结果；搜索时全选只影响当前搜索结果，不改变其他已选技能；
- 支持一次添加一个或多个 ZIP 技能包；
- 支持一次删除一个或多个已选技能；
- 所有登录用户都可在智能体编辑页查看并导入仓库技能，但只有管理员能在本页增删仓库内容。

每个 ZIP 技能包必须包含且只能包含一个 `SKILL.md`；系统读取其中 `name` 作为技能名，保留附属文本和二进制资源。仓库中删除技能后，不会自动改动已导入到智能体目录的历史副本。

点“配置 MCP”会创建 `mcp.json`。其顶层为服务名到 OpenCode MCP 配置的对象，支持 `remote`（URL、headers、OAuth）和 `local`（command、environment、相对 cwd）连接。每个 Agent 最多 16 个服务；运行时服务名会加 Agent key 前缀，MCP 工具默认全局关闭，只对所属 Agent 开启。Header、environment 和 OAuth 字段中的凭据会进入获配用户的只读运行时配置，不应把无关凭据写入 Agent。

Agent key 创建后不可修改。为保证对话接口可用，应以小写字母开头，后续只使用小写字母、数字和连字符，且不能使用 OpenCode 保留名。`agent.md` 必须包含完整 frontmatter、非空正文、名称和说明；`mode` 仅支持 `primary`、`subagent` 或 `all`。`primary` 和 `all` 可作为用户主对话智能体，`subagent` 只出现在协作调用范围内，不进入主智能体选择列表；`primary` 不能作为定时任务的协作智能体。引用的模型、技能和脚本必须存在并通过检查。

“保存并检查”只有在目录检查通过后才会替换正式目录。编辑、重新检查、启用或停用会触发受影响用户的配置处理。停用 Agent 或撤销分配会立即阻止依赖旧配置的新工作，并自动暂停依赖它的个人计划；历史记录和个人文件保留。

删除 Agent 前，必须先在“用户分配”中撤销它对所有用户的分配。删除时需要输入 Agent key 二次确认；确认后会永久删除数据库记录和 `data/agents/<key>/` 配置目录，但不会删除历史会话、历史执行、个人文件或已经暂停的定时任务记录。

## 免密登录

管理员侧栏的“免密登录”位于技能仓库下方，用于维护对端登录所需的共享密钥和账号白名单。免密登录不影响原有账号密码登录。

### 配置步骤

1. 升级前按[部署指南](deployment.md)备份数据库并应用新版本的数据库迁移；既有部署只需更新和启动，不要执行 seed。
2. 与对端安全约定共享密钥。部署目录的 `.env` 中可设置 `OPSHELPER_SSO_SECRET` 作为初始密钥，修改后需重启 API。系统不会自动使用对接说明中的测试密钥，生产应使用双方约定的随机密钥。
3. 如需在管理界面设置或轮换共享密钥，部署 `.env` 中还必须配置独立的 `OPSHELPER_SSO_ENCRYPTION_KEY`，至少 32 个 UTF-8 字节；新部署的 `init` 会自动生成，已有部署需自行生成并配置。妥善备份并保持此密钥不变，丢失或更换后，数据库中已保存的共享密钥将无法解密。不要将密钥提交到仓库或写入日志。
4. 登录管理控制台，进入“免密登录”。页面的共享密钥输入框不回显旧值；输入新值并点击“保存密钥”可设置或轮换密钥。**页面保存的密钥优先于环境变量中的初始密钥**；轮换时要同步通知对端更新。
5. 在“账号白名单”中点击“添加用户”，在弹窗中按用户名或显示名称搜索、勾选用户并点击“添加”；也可在白名单列表中移除用户。添加或移除后自动保存，保存成功后生效；取消弹窗不会更改白名单。保存失败时页面会提示错误，请刷新页面核对实际白名单后重试。已停用用户不可新增；原已选的停用用户和不存在的历史账号仍会显示，可移除。对端传来的账号去除首尾空白并转为小写后，须与白名单及已启用的 opshelper 用户名完整匹配，不使用密码登录的前缀匹配。账号不在白名单、用户不存在或已停用时均拒绝登录；清空白名单会拒绝所有免密登录。白名单按用户名保存：用户改名或删除后，应及时检查并移除旧账号，避免后来创建同名用户时重新获得免密登录资格。

密钥和白名单分别保存：自动保存白名单不会提交输入框中尚未保存的密钥。

在用户旁点击“获取令牌”，系统会使用当前已保存的共享密钥为该用户生成 `account` 令牌，并在弹窗中提供复制。未配置密钥时会报错；如果用户尚未加入已保存的白名单或已停用，弹窗会提示该令牌目前无法登录。未保存的密钥不会参与生成或验证。令牌每次随机生成，可用于联调，但它本身是登录凭证，不要公开、记录或转发。

### 对端入口与联调

1. 对端为已登录用户生成账号令牌：账号用 UTF-8 编码，以双方共享密钥的 UTF-8 前 16 字节（不足补零）作为 AES-128 密钥，使用随机 16 字节 IV、AES-CBC 和 PKCS7 填充加密，再将 `IV || 密文` 编码为无 padding 的 Base64URL。
2. 在对端门户配置 opshelper 的入口地址，例如 `https://opshelper.example/v1/auth/sso`；对端将生成的令牌作为 `account` 查询参数追加，让用户浏览器访问：

   ```text
   https://opshelper.example/v1/auth/sso?account=<令牌>
   ```

3. opshelper 解密并核验账号，通过后建立自己的会话并跳转到 `/gateway/chat`；无效令牌、白名单或用户检查不通过时，跳转登录页并提示失败。普通用户从对端门户点击入口即可，无需手动生成令牌。
4. 联调时分别验证允许账号、未列入白名单、用户不存在或已停用、错误密钥或损坏令牌，并确认现有密码登录正常。不要在日志、工单或聊天中粘贴完整令牌或链接；同时检查外层代理、网关的日志配置。

当前对接令牌没有有效期或完整性签名，账号白名单不能阻止被窃取的令牌重放，也不能证明令牌未被篡改。生产环境必须使用 HTTPS，并通过网络策略限制入口的可达范围；要防止重放和篡改，需要对端协议支持签名、时间戳和一次性 nonce 或安全的服务端换票。

## 用户分配与配置状态

“用户分配”只列出启用用户；只能勾选已启用且检查通过的 Agent。每个非空分配清单至少要有一个 `primary` 或 `all` 模式的 Agent，避免用户只有子智能体而无法发起主对话。分配同时适用于聊天和该用户的个人计划。

保存前页面带有目标代次并发检查；若提示“分配状态已变化”，刷新后重新选择。保存后重点核对：

| 状态 | 含义 | 管理动作 |
| --- | --- | --- |
| 等待当前任务 | 普通更新等待当前执行完成 | 等待，不强制停止用户任务 |
| 正在撤销 | 撤销、停用用户或 Agent 正在清除旧能力 | 等待完成，留意相关计划已暂停 |
| 正在装配 | 正在生成快照、重建或启动运行环境并核对清单 | 等待状态刷新 |
| 已就绪 | 已应用代次和实际 Agent 清单可用 | 核对两组代次和清单一致 |
| 已冻结 | 系统不能证明运行环境与目标配置一致 | 阅读冻结原因，修复依赖后点“重新装配” |

同一用户获配的多个 Agent 共用该用户固定容器、workspace、state、模型和工具环境，可以在一次执行内协作。不同用户的 Agent 清单和挂载目录分别装配。

## 容器管理

“容器管理”可按状态筛选、查看最近活动、读取最近 100 至 1000 行日志，并执行启动、停止、重建环境或移除容器。

- 启动：启动现有容器；若配置或镜像不匹配，服务会按当前受管运行时处理。
- 停止：停止进程，保留 workspace、state 和数据库记录。
- 重建环境：使用当前镜像重建容器，保留用户文件、OpenCode state 和数据库记录，适合运行镜像或容器定义更新后使用。
- 移除容器：只移除 Docker 容器，保留用户文件、OpenCode state、受管快照、Agent 分配和数据库记录；下次使用时会自动重建。

活动执行或待恢复状态存在时，停止、重启、重建环境和移除容器都会被拒绝。先让用户完成/停止执行，或在对话中完成“重新核对状态”。生命周期操作正在进行时会返回冲突或暂时不可用，等待当前操作结束后再试。

“保持容器运行”未启用时，worker 会在空闲阈值后停止容器；活动执行、有效租约、恢复状态或配置未就绪的容器不会被空闲回收。

## 日常检查

出现用户无法工作时，按以下顺序检查：

1. 用户账号仍启用；
2. 模型连接存在且目标模型有效；
3. 所需 Agent 已启用并检查通过；
4. 用户分配正确，配置状态为“已就绪”；
5. 已应用代次等于目标代次，实际 Agent 清单等于期望清单；
6. 容器可以启动，日志中没有 OpenCode 健康检查、挂载或鉴权错误；
7. `/health` 返回 API 健康结果。

`/health` 只说明 API 能响应，不能单独证明 Web、worker、PostgreSQL、用户容器、模型连接或定时执行正常。
